# BoxLab · 推箱工坊

一款采用固定视角 3D 表现的推箱子游戏，包含新手教程、正式关卡和内置关卡编辑器。玩家可以体验机关谜题，也可以在独立运行的游戏中创建、保存和分享自己的地图。

开发环境：**Unity 2022.3.51f1c1 · Built-in Render Pipeline · Windows x64**。

## 运行与构建

1. 下载或克隆本仓库，在 Unity Hub 中添加包含 `Assets`、`Packages`、`ProjectSettings` 的工程根目录。
2. 使用上述 Unity 版本打开工程，等待依赖包解析、资源导入和脚本编译完成。
3. 打开 `Assets/Scenes/BoxLab.unity`，点击 **Play** 进入主菜单。
4. 构建独立程序时，先安装对应的 **Windows Build Support**，再选择 `Tools → BoxLab → 玩家工坊 → 构建 Windows 玩家版`。

构建输出为 `Builds/Windows/BoxLab.exe`。独立程序运行不需要 Unity，分发时请保留整个 `Builds/Windows` 文件夹。构建日志保存在 `BoxLabEvidence/player-build.txt`。

## 游戏内容

- **12 关新手教程**：逐步认识推动、冰面、按钮、箭头、对象通道、传送、空洞与坍塌道路，并练习基础组合。
- **6 关正式关卡**：围绕箱子分工、机关联动和路线规划逐步增加难度。
- **玩家工坊**：创建地图、保存草稿、连接机关、试玩与分享；预设关卡也可以复制后编辑。
- **本地进度与设置**：继续上次游玩、记录通关情况，调整音量、游戏速度、窗口模式和氛围特效。

主菜单分别提供“新手教程”“正式关卡”“我的关卡”和“创作新关卡”入口。帮助页面介绍基本操作与地块效果，首次创作时提供分步引导。

## 游玩操作

让所有目标点都被箱子覆盖即可通关。箱子只能推动，不能拉动；箱子数量可以多于目标数量。

| 操作 | 功能 |
| --- | --- |
| 方向键 / WASD | 移动人物；常规情况下，每次推动一只箱子一格 |
| Z / Backspace | 撤销上一次操作，包括该次操作触发的机关效果 |
| R | 重开当前关卡；重开后仍可撤销，恢复重开前的局面 |
| Esc | 关闭弹窗，或返回关卡列表 / 编辑器 |

一次操作引起的自动移动与机关动画结束后，才接受下一次移动指令。正式游玩会自动保存进度，编辑器内的试玩不覆盖正式进度。

## 地块与机关

| 元素 | 规则 |
| --- | --- |
| 普通地面 | 人物与箱子均可经过 |
| 目标点 | 所有目标被箱子覆盖时胜利；不与特殊地面叠加 |
| 冰面 | 箱子沿进入方向额外移动一格，连续冰面逐格触发；人物不滑行 |
| 箭头 | 箱子进入后沿箭头方向移动一格；人物不受影响 |
| 压力按钮 | 人物或箱子占用时激活，离开后解除；门要求全部关联按钮同时激活 |
| 旋转按钮 | 每次从空闲变为受压，让关联箭头顺时针旋转 90°；离开时不旋转 |
| 人物通道 | 仅人物可进入 |
| 箱子通道 | 仅箱子可进入；从此格推走箱子时，人物留在原地 |
| 传送入口 / 出口 | 箱子从入口正面进入，传到出口并沿出口朝向走出一格；出口、落点或通路受阻时不传送。人物可步行经过，但不会传送 |
| 空洞 | 人物不可进入；箱子进入后消失，剩余箱子少于目标数量时失败，可撤销 |
| 坍塌道路 | 人物或箱子离开后变为空洞；推走上面的箱子时，人物留在原地 |
| 墙 / 门 | 放置在格子公共边上，双向阻挡；门替换该边的墙，满足按钮条件后开放 |

人物推动箱子并接替它占据按钮时，按钮视为持续受压。自动移动遇到墙或其他箱子会停止，不会连锁推动；新机关的移动效果接替旧效果。发生规则循环时，系统中断并回退整次输入。

## 玩家关卡编辑器

玩家工坊使用固定素材预设，通过摆放、旋转和连线组合地图，无需编程。地图宽高可各设为 **2～32 格**，未完成的地图也能保存为草稿。

### 摆放与调整

支持从工具箱拖入、点击素材后放置，以及先选格子或公共边再选素材。绿色预览表示可以放置，红色表示受阻。放置结束后自动取消选择，方便继续操作其他位置。

| 操作 | 功能 |
| --- | --- |
| Q / E | 旋转箭头、传送门等有朝向的地块；墙和门自动贴合所选边 |
| Ctrl+Z / Ctrl+Y | 撤销 / 重做；连续涂抹按一笔记录 |
| Delete / 红叉 / 拖入垃圾桶 | 删除选中内容 |
| 滚轮 / 中键拖动 | 缩放 / 平移地图；“适应地图”恢复全图 |

同一格有多个内容时，默认选中最近放置的一层，也可切换“地面 / 物件”选择。关卡可设置名称与说明，说明会在游玩时显示。修改尺寸和删除内容均可撤销。

### 连接机关

选择“连线”后，先点击按钮，再点击对应机关，完成一条连接后自动退出连线模式。

- 压力按钮连接门，旋转按钮连接箭头。每个门或箭头最多关联 **3 个按钮**；门至少连接一个按钮，箭头可以独立使用。
- 移动机关保留连接，删除机关会清理相关连接；连线也可以单独选中并删除。
- 编辑时显示连线，游玩时以门上的颜色与符号指示灯表达按钮状态。
- 传送入口与出口在放置时自动配对，选中一端可查看另一端；用 Q / E 调整方向，以地面箭头为准。

### 校验与试玩

点击“试玩”后，系统先检查人物、箱子、目标、传送配对及机关关联。可定位的问题会提供“定位”入口；结构错误必须修正，未完成的地图仍可保存。

随后进行有时间与局面数量上限的可解性搜索：找到解即可试玩，穷尽无解则提示修改；达到搜索上限只表示尚未验证，仍可选择手动试玩。试玩使用地图副本，返回时保留编辑原稿。

## 本地保存与分享

存档保存在 `Application.persistentDataPath/WorkshopV2`，可从设置页面打开该目录。

| 内容 | 存储位置 |
| --- | --- |
| 自建地图 | `Maps/` 下的 `.boxmap` 文件 |
| 最近游玩进度与撤销记录 | `continue.json` |
| 设置与通关记录 | `settings.json` |
| 删除地图的备份 | `Deleted/` |

保存使用临时文件写入、替换与备份机制。保存失败时保留当前编辑内容并提示；地图主文件损坏时尝试读取有效备份。

在“我的关卡”中选择“分享”，即可复制以 `BL2:` 开头的完整分享码。另一位玩家通过“导入分享码”还原地图，并获得独立副本，不会覆盖已有地图。分享码包含地图数据，无需服务器；草稿也可以分享。

本项目使用本地存档，不提供账号、云存档或联网服务。

## 实现与规则扩展

规则采用整数格子坐标和确定性状态转换，不依赖物理模拟。地图编辑、运行与求解器共用地图数据和规则逻辑；运行状态独立于编辑原稿，撤销恢复整次输入前的状态。

源码位于 `Assets/Scripts/BoxLab`：

| 目录或文件 | 职责 |
| --- | --- |
| `Core/` | 格子与公共边数据、规则执行、结构校验、可解性搜索及预设关卡 |
| `Runtime/WorkshopApp*.cs` | 菜单、关卡列表、编辑、试玩与游玩流程 |
| `Runtime/PlayerEditor.cs`、`PlayerEditing.cs` | 可视化编辑交互与编辑撤销 |
| `Runtime/PlayerStorage.cs` | 地图、分享码、进度与设置的读写 |
| `Runtime/BoardView*.cs`、`GameController.cs` | 场景表现、输入、动画与游玩撤销 |
| `Runtime/WorkshopTheme.cs`、`WorkshopAudio.cs` | 界面样式与程序合成音效 |
| `Editor/` | Unity 规则编辑工具、资源生成、验证和构建 |

除玩家工坊外，工程还提供面向开发的表单式规则工具：打开 `Tools → BoxLab → 地图与规则编辑器`，使用 `Assets/BoxLab/BoxProject.asset`。

该工具可以组合对象类型、进入条件、条件组、进入 / 离开事件，以及移动、传送、地形替换、移除箱子等基础动作。已有能力可以通过配置重新组合；增加系统尚未支持的基础能力仍需扩展代码。

玩家工坊的固定预设与 Unity 规则库分别管理。玩家分享码用于固定预设地图，Unity 工具的导出则包含地图与规则库，两种格式不能混用。独立程序不依赖 `UnityEditor`。

### 开发工具

`Tools → BoxLab → 玩家工坊` 提供以下入口：

- **验证玩家版完整数据流程**：检查核心规则、编辑命令、存储分享、异常数据和关卡解法，使用隔离存储目录。
- **审计美术资源（只读）**：检查运行资源与生成器依赖，输出 `BoxLabEvidence/art-audit.json`。
- **构建 Windows 玩家版**：生成运行资源并构建独立程序。

缓存、构建输出、验证报告与个人存档均不属于源码提交内容；仓库包含运行和重新构建所需的资源与配置。

## 素材来源

美术资源集中在 `Assets/BoxLabArt`，第三方素材保留各自的原始 **CC0** 许可与 `SOURCE.md` 来源记录。

| 素材包 | 用途 | 工程目录 |
| --- | --- | --- |
| [KayKit Dungeon](https://kaylousberg.itch.io/kaykit-dungeon-pack) | 地板、墙、木箱、碎裂石板与石拱门 | `ThirdParty/KayKitDungeon` |
| [KayKit Adventurers](https://kaylousberg.itch.io/kaykit-adventurers) | 法师人物 | `ThirdParty/KayKitAdventurers` |
| [Kenney Particle Pack](https://kenney.nl/assets/particle-pack) | 冰面雾气贴图 | `ThirdParty/KenneyParticlePack` |
| [Kenney UI Pack - Adventure](https://kenney.nl/assets/ui-pack-adventure) | 界面面板与按钮 | `ThirdParty/KenneyUIAdventure` |

表中目录均相对于 `Assets/BoxLabArt`。运行预制体与缩略图位于 `Resources/BoxLabArt`；部分源模型用于重新生成运行素材，因此应与贴图、材质和 `.meta` 一并保留。声音由 `WorkshopAudio.cs` 合成，不含第三方录音或音乐。

如需替换美术，可使用 `Tools → BoxLab → 生成可选 CC0 美术预设` 重建预制体与缩略图。维护 `ArtSetup.SourceAssetPaths` 的源文件清单，并保持运行资源名称、路径、格子尺寸和地面原点一致。
