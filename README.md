# BoxLab · 推箱工坊

Unity **2022.3.51f1c1** · Built-in · Windows x64。固定正交视角的 3D 表现，整数格子规则，不使用物理模拟。

**验收状态（2026-10-01）：12 关新手教程与 6 关正式关卡均已在实际控制器中回放通关；Windows 最终构建 0 错误 / 0 警告。** 已验证无 Library 缓存首次导入、分合集导航与续档、9 步创作引导的真实鼠标键盘操作，以及 960 × 600 / 2504 × 850 界面。

## 启动与游玩

1. 在 Unity Hub 中打开包含 `Assets`、`Packages`、`ProjectSettings` 的工程根目录，使用上述 Unity 版本，等待资源导入和脚本编译完成。
2. 打开 `Assets/Scenes/BoxLab.unity`，点击 Play，进入玩家主菜单。若场景尚未生成，可使用 `Tools/BoxLab/初始化示例工程` 创建；已有作者资产不会因此被替换。
3. 独立 Windows 程序的构建位置是 `Builds/Windows/BoxLab.exe`。运行不需要 Unity，分发时必须带上整个 `Builds/Windows` 文件夹。

玩家主菜单提供独立的“新手教程”和“正式关卡”入口，以及继续上次进度、我的关卡、创作新关卡、设置和帮助。第一次进入编辑器会显示操作引导，之后点击主菜单“帮助”或右上角“? 帮助”查看；不使用 F1 快捷键。通用指南分两页，用对应素材缩略图逐行介绍地块效果，并单独列出基本操作与地图编辑摘要。窗口最低 **960 × 600**，默认 **1280 × 800**；设置页可切换窗口/全屏、游戏速度、氛围特效，并调整音量或静音。

关卡分为 **12 关新手教程 + 6 关正式关卡**。第 07 关新增“只让箱子经过”，后续显示编号顺延；原有 11 关教程及前 3 关正式关的持久 ID 不变，已有通关记录与续档保持兼容。前 10 关依次介绍基本推动、连续冰面、压力板开门、方向箭头、旋转按钮、人物通道、箱子通道、定向传送、空洞和坍塌道路；最后两关“留守与运送”“接力路线”练习简单组合。

正式关卡使用现有机制，逐步增加箱子分工和操作时序的要求：

| 正式关卡 | 配置 | 主要问题 |
| --- | --- | --- |
| 最后一个岗位 | 7 × 6，2 箱 / 2 目标 | 临时守住压力板的箱子，何时才能完成自己的目标？ |
| 两次发车 | 7 × 6，2 箱 / 2 目标 | 同一条传送与冰面运输线，怎样先后把货物送往两个方向？ |
| 岗位与时序 | 7 × 7，3 箱 / 2 目标 | 留箱开门，同时处理装货路线上的旋转按钮，安排每批货物出发时的方向。 |
| 双岗接力 | 8 × 7，3 箱 / 3 目标 | 两箱同时留守开门，货物与人物分路接力，再回收两只岗位箱。 |
| 最后一趟 | 8 × 8，4 箱 / 3 目标 | 清理桥头、安排单次裂桥货运，按站位限制填目标，最后用传送送货。 |
| 双岗交接 | 9 × 8，4 箱 / 3 目标 | 留守箱与人物共同开门，先清空收货口，再旋转分流不同批次。 |

关卡可以从各自列表直接开始，也可复制到工坊改造；通关后，同一合集的“下一关”会以金色高亮提示，尺寸和布局不变。合集末关或编辑器试玩则高亮相应的创作/返回入口。所有正式关卡都有经过实际规则回放的解法，设计阶段另做过关键机关禁用与目标顺序对照。新增 4～6 关按岗位回收、不可逆路线、运输调度组织进阶，不以步数更长作为难度证明；实际体验难度仍需新玩家试玩确认。

| 操作 | 行为 |
| --- | --- |
| 方向键 / WASD | 一次移动一格，常规推动一只箱子一格 |
| Z / Backspace | 撤销整次指令，包括自动移动、坍塌、箱子消失、机关朝向和计数 |
| R | 重开本关；之后按 Z 可以撤销这次重开，恢复重开前局面 |
| Esc | 关闭当前弹窗，或从游玩返回关卡列表 / 编辑器 |

正在处理机关或播放移动动画时，新移动指令不排队。重开保留此前的撤销历史；已经处于完全相同的初始状态时，重复重开不额外记录。

## 玩家关卡编辑器

玩家工坊使用**固定素材预设**，通过摆放、旋转和连线制作地图，无需 Unity 或编程。地图宽高可各设为 2～32 格，未完成内容可以先保存为草稿。

工坊入门引导在新建的练习草稿中进行，不修改已有地图。9 个操作步骤依次完成：放人物、放箱子、放目标、放压力板、把墙替换成门、连接按钮和门、命名、填写说明、试玩通关；完成后可以保存或继续改造。代码步骤从 0 计数，6 为名称、7 为说明、8 为试玩、9 为完成状态。

普通编辑的工具、分类和拿起的素材用棕色表示选中，棋盘选中位置采用淡色覆盖。金色边框用于系统提示；教程第 3、5、6 步分别指向地面分类、墙/门分类和连线功能，切换后再强调相应素材或棋盘位置。

放置支持三种方式：先选格子/公共边再点素材；从工具箱拖入；点击素材拿起后在地图上点击或连续涂抹。绿色表示可放，红色表示受阻并提供原因。一次放置、移动或整笔涂抹结束后清除持物、选中格和删除气泡；失败时保留原件及重试机会。需要调整时，再单独点选对象。

- `Q / E` 旋转箭头、传送门等有朝向的地块；墙和门自动贴合所选公共边。
- `Ctrl+Z / Ctrl+Y` 撤销 / 重做，一笔连续涂抹算一次操作。
- 滚轮缩放，中键拖动平移；“适应地图”恢复全图。
- 选中后按 Delete、点红叉，或拖入垃圾桶删除。默认选择最近放置的一层，也可切换“地面 / 物件”访问被遮挡内容；删除顺序随草稿与分享保存。
- 名称最多 80 字。“说明”可编辑最多 400 字的关卡提示，应用后可以撤销，保存后在游玩中显示；取消不改变原说明。旧地图的较长说明仍可读取，主动修改时才应用新长度限制。
- 地图可以改尺寸。缩小时裁掉范围外内容及关联，可撤销；缺少必要要素的地图仍能保存草稿，但不能直接试玩。

**机关连线**：普通压力按钮连到门，旋转按钮连到箭头。每个目标最多关联 3 个按钮；门至少关联 1 个，箭头可以没有关联。移动机关保留连接，删除机关清理连接，也可单独选中一条线删除。编辑时显示虚线；游玩时隐藏连线，门上的颜色与符号指示灯对应压力按钮，全部点亮才开门。

**传送配对**：放置时自动配对入口与出口。选中一端会高亮另一端并显示配对线；Q/E 调整门口方向。入口从正面接收箱子，出口把箱子送到正前方一格，实际方向以地面箭头为准。

**校验与试玩**：点击试玩先做结构校验。可定位的问题有“定位”按钮，跳到对应格子或公共边；缺人物、目标等全局问题提供文字说明。错误需要修正，警告允许继续检查。随后执行有时间和局面数量上限的可解性搜索：找到解即可试玩，穷尽无解则提示修改，达到预算仅表示“尚未验证”，可以选择继续手动试玩。试玩使用地图副本，返回编辑器后保持原稿。

## 规则一览

| 元素 | 玩家版固定行为 |
| --- | --- |
| 人物 | 只有一个，没有血量、生存或切换角色系统 |
| 目标 | 中心金色向周边透明渐隐，保留目标粒子；至少一个；初始箱子数不能少于目标数；所有目标被箱子覆盖即胜利，多余箱子无需归位 |
| 普通地面 | 人物、箱子可经过；目标不与特殊地面叠加 |
| 冰面 | 箱子进入后沿进入方向额外走一格，连续冰面逐格触发；人物不滑 |
| 箭头 | 箱子进入后沿当前箭头方向走一格；人物不受影响 |
| 压力按钮 | 人物或箱子持续占用时激活，门要求全部关联按钮同时受压 |
| 旋转按钮 | 从空闲变为受压时让关联箭头顺时针转 90°；离开或持续受压不转，开局已受压不额外触发 |
| 人物通道 | 人物可通过，箱子不能进入；地块只显示人物图标 |
| 箱子通道 | 箱子可进入，人物不能进入；推走此格上的箱子后人物留在原地，需要绕路；地块只显示箱子图标 |
| 传送入口 / 出口 | 箱子从入口正面进入后传到出口，再沿出口朝向走一格；出口、落点或通路受阻则不传送，箱子留在入口；从其他方向进入不触发，人物步行经过但不传送 |
| 空洞 | 人物不能进入；箱子进入后消失，仅剩余箱子少于目标数时失败，可撤销 |
| 坍塌道路 | 物件离开后立即变为空洞；推走箱子时人物留在原地，需要绕路 |
| 墙 / 门 | 位于相邻格子的公共边，双向阻挡；门覆写该边墙规则，关闭时不能穿过 |

普通推动中，箱子离开按钮而人物接替原格，视为持续受压。新机关效果接替旧自动移动效果；自动移动撞到墙或箱子会停止，不会继续推另一只箱子。规则循环会中断并回退整次输入。表现、粒子和声音均不参与规则计算。

## 本地保存与文字分享

设置页可打开存档目录，默认是 `Application.persistentDataPath/WorkshopV2`，与工程源文件分开：

| 路径 | 内容 |
| --- | --- |
| `Maps/` | `.boxmap` 地图：布局、方向、配对、连线、说明与编辑层级 |
| `continue.json` | 最近一次正式游玩的局面和撤销记录；编辑器试玩不覆盖它 |
| `settings.json` | 显示、声音等偏好和关卡完成记录 |
| `Deleted/` | 界面删除地图后的备份 |
| `SharedMaps/` | 旧版文件分享兼容目录 |

地图与进度独立保存。写入先使用临时文件，再替换正式文件并保留上一版 `.bak`；地图主文件损坏时尝试读取有效备份。保存失败提供提示，编辑内容不因失败被标为已保存；离开或退出前保存失败会保留当前页面。地图修改后，旧进度不会套用到不同版本的地图上。

在“我的关卡 → 分享”复制完整分享码；另一位玩家在“导入分享码”中粘贴，导入为自己的独立副本。分享码以 `BL2:` 开头，包含压缩后的完整地图，离线可用，允许换行排版；草稿也能分享。导入先验证版本、大小、格式和校验信息，成功后生成新编号，不覆盖原图。旧 `.boxmap` 文件仍可从“导入旧地图文件”读取。

地图与进度继续使用 v2 格式，本轮不要求迁移原有玩家地图。正式进度最多保存最近 128 次撤销；编辑器最多保留 100 次撤销。不提供账号、云存档或联网服务。

## 实现与规则扩展

源码位于 `Assets/Scripts/BoxLab`：

- `Core/`：格子与公共边数据、可组合规则、确定性状态转换、结构校验、增量 BFS、新手教程与正式关卡。`PlayerRules.CreateDemoLevels()` 提供 12 关教程，并保留原 11 关持久 ID，`CreateCampaignLevels()` 提供独立的 6 关；规则只处理整数坐标和逻辑状态，不读取 Transform 或物理碰撞。
- `Runtime/WorkshopApp*.cs`：玩家菜单、弹窗、编辑 / 试玩 / 正式游玩流程。
- `Runtime/PlayerEditor.cs`、`PlayerEditing.cs`：可视化交互与可撤销编辑操作。
- `Runtime/PlayerStorage.cs`：草稿、分享、进度和设置的磁盘读写。
- `Runtime/BoardView*.cs`、`GameController.cs`：场景表现、输入锁、动画、快照与撤销。
- `Runtime/WorkshopTheme.cs`、`WorkshopAudio.cs`：界面样式和原创程序合成反馈音。
- `Editor/`：Unity 作者工具、初始化、素材生成、资源审计、验证与构建。独立程序不依赖 UnityEditor。

制作流程是“**组合 → 校验 → 运行**”：地图数据同时供编辑预览、游戏和求解器使用；试玩与运行状态使用副本，撤销恢复完整状态。`RuleAnalysis` 分析地形变更后可能需要的关联，编辑工具与校验共用该分析。

需要展示规则复用时，可打开 `Tools/BoxLab/地图与规则编辑器`，使用 `Assets/BoxLab/BoxProject.asset`。Unity 作者工具支持可视化地图、实时场景预览，以及表单式规则配置：对象类型、进入条件、嵌套条件组、取反、数量阈值、进入 / 离开事件、移动、传送、地形替换和移除箱子等动作。已有基础能力可以重新组合并配置实例关联；增加系统尚无的基本能力仍需修改代码。

玩家版 `PlayerRules` 固定预设与 Unity 作者规则库分开，避免作者实验修改玩家规则或旧资产。玩家分享格式用于固定预设地图；作者工具另有包含地图及完整规则库的导出格式，两种导出不能混用。

## 构建、验收与源工程提交

Unity 菜单 `Tools/BoxLab/玩家工坊` 提供：

1. **验证玩家版完整数据流程**：核心规则、编辑命令、异常数据、存储分享、关卡可解与回放；使用隔离目录。
2. **构建 Windows 玩家版**：准备美术，审计资源，输出 `Builds/Windows`，把错误 / 警告数量写入 `BoxLabEvidence/player-build.txt`。需要安装对应 Unity Windows Build Support。

独立程序验收入口：`-boxlabWorkshopVerify -boxlabData <隔离目录> -boxlabEvidence <报告目录>`；`-boxlabWorkshopPhase write` / `read` 用于跨进程续档检查。普通启动不会执行验收。自动回放、真实鼠标键盘交互和人工听音分别记录；仅相机截图不能作为界面验收或音频可听见的证据。
